# Prisma ORM example

A small checkout for the last desk lamp in stock, written with Prisma ORM 7.10.0.
`@prisma/client` and `@prisma/adapter-pg` are pinned to **7.10.0** and node-postgres
to **8.23.0**. Prisma 7 has no native query engine process: the generated client
compiles queries in-process with a WebAssembly query compiler and sends them
through the pg driver adapter, which is the node-postgres protocol path
Interleave already schedules. Prisma 8 (the registry's `latest` tag currently
points at a release candidate) is not covered.

This is a constructed example for Interleave's own qualification, not a
historical Prisma defect.

## Layout

| Path | Role |
| --- | --- |
| `package.json`, `package-lock.json` | The application. Runtime dependencies only: `@prisma/client`, `@prisma/adapter-pg`, `pg` |
| `prisma/schema.prisma` | Models `Product` (`products`) and `Order` (`orders`, unique per product and buyer) |
| `prisma/migrations/0_init/migration.sql` | Generated by the pinned CLI with `prisma migrate diff --from-empty --to-schema`; setup applies it to every new database |
| `generator/` | The pinned Prisma CLI and TypeScript, with their own lock and `prisma.config.ts` |
| `generated/prisma/` | The generated client (not committed). Produced by `prisma generate` |
| `src/db.ts` | `withPrisma(context, operation, options)`: one PrismaClient per actor |
| `src/purchases.ts` | The unsafe purchase and three safe alternatives |
| `src/checkout.ts` | `checkout`, the operation under test. It starts as the unsafe purchase |
| `src/orders.ts` | Order create, update, read and delete around a rolled-back duplicate |
| `scenario.ts` | `createCheckoutScenario(behavior, options)`; the default export tests `checkout` |

The generator is configured with `generatedFileExtension = "ts"` and
`importFileExtension = "ts"`. Node.js 22.18+ and 24 load the generated
TypeScript directly, so Interleave records the generated client files as part of
the scenario's source, with no separate build step. The application code uses
only erasable TypeScript syntax, which `tsconfig.json` enforces.

### Why the Prisma CLI is in a separate directory

Interleave's source identity hashes every installed file of every package the
scenario can load, including installed optional peer dependencies. `@prisma/client`
declares optional peers on `prisma` (the CLI) and `typescript`.

- With only the runtime dependencies, the recorded identity is about 82.5 MB in
  about 600 files. `@prisma/client` alone installs 74,458,946 bytes in 75 files.
  This fits the 128 MiB default source identity budget.
- With the CLI installed next to the client, as `npm install -D prisma` would do,
  the same scenario's package closure measured 310,499,758 bytes in 10,437 files
  and 158 packages. It includes a 25,592,784-byte native schema engine that the
  CLI downloads into `@prisma/engines` the first time it runs, even for `prisma
  generate`. That closure exceeds every capture bound (10,000 files, the byte
  total even at its 256 MiB maximum, and 16 MiB per file). An `interleave run`
  in that layout stopped as `inconclusive` (exit 4) with
  `Source identity byte limit exceeded`, before any SQL ran.

Keep generation tooling out of the recorded application's Node resolution path.
The same applies to ancestors: a package missing from the application's own
`node_modules` resolves from any parent directory's `node_modules`, and would be
recorded from there. The qualification gate refuses an evidence directory with a
`node_modules` ancestor.

## Actor client

```ts
import type { ActorContext } from '@pavangupta352/interleave';
import { withPrisma } from './src/db.ts';
import { checkout } from './src/checkout.ts';

const buy = (context: ActorContext) => withPrisma(context, prisma => checkout(prisma, 1, context.actor));
```

`withPrisma` creates `new PrismaClient({ adapter: new PrismaPg({ connectionString, max: 1, … }) })`
from the actor's endpoint, so each actor has exactly one PostgreSQL connection.
It calls `$disconnect()` when the operation settles and as soon as the actor's
`AbortSignal` fires. `{ preparedStatements: true }` adds the adapter's
`statementNameGenerator`, naming each statement after a hash of its SQL so
node-postgres prepares it once per connection and reuses it.

Every interactive transaction sets `maxWait: 10_000` and `timeout: 60_000`.
Prisma's defaults (2 and 5 seconds) could otherwise end a transaction while
Interleave is holding its next command, and the resulting error would look like
an application failure.

## Behaviors

| Behavior | Application code | Expected outcome |
| --- | --- | --- |
| `checkout` (default) | `src/checkout.ts`, initially `readThenWrite` | Violation when both buyers read the last unit |
| `read-then-write` | In one READ COMMITTED transaction: `findUniqueOrThrow`, `order.create`, then `product.update` with the stock that was read minus one | Violation: the second UPDATE waits for the first buyer's row lock, then writes the same stale remainder |
| `compare-and-set` | The same transaction, but `updateMany` only where `stock` still equals the value read. No match throws, rolling back the order, and the whole purchase restarts (up to three attempts) | Passes. A losing buyer sees the new stock and reports `sold-out` |
| `conditional-decrement` | `updateMany` with `stock: { gte: 1 }` and `decrement: 1`, then `order.create` if a row matched | Passes |
| `serializable-retry` | `read-then-write` at `Serializable` isolation. On `P2034` (SQLSTATE 40001) it checks that the failed attempt's order is gone and retries the whole transaction | Passes |
| `serializable-no-retry` | The same without retry | The `P2034` rejects the actor: `actor-error`, invariant not evaluated |
| `order-lifecycle` | A transaction creates an order and then a duplicate. The unique index rejects it (SQLSTATE 23505, `P2002`) and the transaction rolls back. The client then counts, creates, updates, reads and deletes an order | Passes; no orders remain |

The invariant checks that accepted orders never exceed the initial stock of
one, that stock plus orders equals that initial stock, and that every buyer who
reported `ordered` has a stored order. `order-lifecycle` instead checks that no
orders remain and each actor observed P2002 and the expected CRUD values.

## Try it

Install Interleave from a package archive (see the
[getting-started guide](../../docs/getting-started.md#install-a-source-build-into-an-application)),
then, from a copy of this directory that has no `node_modules` in any parent
directory:

```sh
npm ci
npm install --save-exact /path/to/pavangupta352-interleave-<version>.tgz
npm ci --prefix generator --ignore-scripts
(cd generator && npx prisma generate)
export TEST_DATABASE_URL='<dedicated PostgreSQL administrator URL>'
npx interleave run scenario.ts --include prisma --timeout-ms 30000 --plan alice,bob,alice,bob --max-runs 1 --out oversell.json
npx interleave replay scenario.ts oversell.json --timeout-ms 30000
npx interleave minimize scenario.ts oversell.json --timeout-ms 30000 --out minimal.json
```

`--include prisma` records the schema and the migration that setup reads.
Each run's deadline also covers capturing the roughly 82 MB source identity
before and after execution and starting two Prisma clients in a new worker.
Most observed runs took one to three seconds, but with the default 10-second
deadline one run stopped as `inconclusive` (`Source identity deadline
exceeded`) while the host's load average was above 30, ending that search with
exit 4. These commands allow 30 seconds per run, as the qualification gate does.
`prisma generate` and `prisma migrate diff` do not connect to a database;
`generator/prisma.config.ts` reads `DATABASE_URL` only for commands that do.
The CLI downloads its schema engine from Prisma's binary host on first use.

The run and the exact replay report the violation (exit 1), and minimization
reduces the ten recorded choices to zero because Interleave's fair fallback alone
reproduces it.

To apply the repair, change both occurrences of `readThenWrite` in
`src/checkout.ts` to `compareAndSet`, then:

```sh
npx interleave replay scenario.ts oversell.json --timeout-ms 30000
npx interleave replay scenario.ts oversell.json --guided --timeout-ms 30000
npx interleave run scenario.ts --include prisma --timeout-ms 30000 --max-runs 400 --total-timeout-ms 2700000
```

Exact replay now reports `incompatible` (exit 3) because the recorded source
changed. The guided rerun follows the recorded actor order against the repaired
code and passes (exit 0). The fresh search explores 363 schedules, all passing,
until its frontier is exhausted (exit 0). Each schedule starts a new worker,
database and two Prisma clients, so the search is slow. In the qualification
runs, two at a time on a shared host, it took 9 to 18 minutes, with median runs
of 1.4 to 2.5 seconds and the slowest at 18.4 seconds. When other work had
pushed the host's load average near 30, a 900-second budget covered only 182
schedules. A search that reaches its budget stops with exit 4 and `deadline`,
which does not establish the repair; the default 60-second budget is far too
small here.

## Qualification gate

`scripts/test-prisma.mjs` (`npm run test:prisma` from the repository root) copies
this directory, without installed or generated files, into a new application
directory. It installs the pinned application lock plus the Interleave archive
under test, installs the generator lock with scripts disabled, runs
`prisma generate`, checks that `prisma migrate diff` reproduces the committed
migration byte for byte, and type-checks the example against the generated
client. It then runs `test/prisma/functional.mjs` inside that application. The
cases run the installed `interleave` CLI against real PostgreSQL; the API case
calls the installed library instead.

| Case | Required observations |
| --- | --- |
| Unsafe checkout (CLI) | `run --plan alice,bob,alice,bob` records a violation (exit 1): `Accepted orders exceed the available stock`. BEGIN and COMMIT are simple queries; SELECT, INSERT and UPDATE are parameterized extended-protocol cycles. Bob's UPDATE waits on a `Lock` held by alice's backend. Each actor uses one connection. The recorded source includes `generated/prisma/client.ts`, `internal/class.ts`, `internal/prismaNamespace.ts`, `enums.ts`, the schema and the migration, and every recorded generated-file hash matches the file on disk. The dependency graph contains `@prisma/client` 7.10.0, `@prisma/adapter-pg` 7.10.0 and `pg` 8.23.0, records the `prisma` and `typescript` peers as missing, and contains no CLI or engine package. Exact replay repeats the failure, actor values, source and fixture identity and step fingerprints |
| Library API | `explore` (file target) finds the violation, `replay` repeats it, and `minimize` reports `locally-minimal` with the same failure |
| CLI minimization | `locally-minimal` with the same failure fingerprint and all ten SQL steps |
| Edited generated client | After a comment is appended to `generated/prisma/internal/class.ts`, exact replay is `incompatible` (exit 3) with an empty trace, before any import, setup or invariant call. The original bytes are restored |
| Schema change | Adding a field to `Product` and regenerating changes `internal/class.ts`; exact replay is `incompatible` before import or setup. Restoring the schema and regenerating reproduces every recorded generated file byte for byte, and exact replay repeats the violation |
| Shared export | Exits 2 with `Archive download exceeds 16 MiB` and creates no bundle (see Limits) |
| Serializable retry | With both buyers inside overlapping transactions, bob's UPDATE waits on alice's lock and fails with 40001 in transaction state E after alice's COMMIT. Bob rolls back, finds no order of his, and retries with a fresh read: `{ status: 'sold-out', attempts: 2, retried: ['P2034'] }` |
| Serializable without retry | The same 40001 rejects bob with Prisma's write-conflict error. Outcome `actor-error` (exit 2); the invariant journal has no entry; ROLLBACK is bob's last command |
| Order lifecycle | Per actor: BEGIN, INSERT, INSERT failing with 23505 in state E, ROLLBACK to state I, then COUNT, INSERT, UPDATE, SELECT and DELETE on the same connection without error |
| Prepared statements | `compare-and-set` with `preparedStatements: true` under the conflicting order. Every command, including BEGIN and ROLLBACK, is a named extended-protocol cycle. Each actor's `pg_prepared_statements` holds exactly one `prisma_…` statement per distinct SQL text it ran; bob's retried BEGIN and SELECT reused the statements prepared before his rollback. Exact replay repeats the run |
| Conditional decrement | A fresh search exhausts its frontier with every run passing. A guided rerun of the unsafe recording is `incompatible` (exit 3): `Schedule asks for bob, which cannot issue its next query` |
| Repair | `src/checkout.ts` switched to `compareAndSet`. Exact replay of the original violation is `incompatible` (exit 3) before import. The guided rerun consumes the whole recorded actor order and passes (exit 0): bob's conditional UPDATE waits for alice, matches no row, rolls back his order and retries. A fresh search exhausts its frontier with every run passing (exit 0) |
| Cleanup | Every generated database and its backends are absent, every command process has exited, and the application lock is unchanged |

Observed on 2026-09-27 with the Interleave 0.1.0-dev.0 archive built from commit
`418a970` (SHA-256 `74cda8ab…`), on macOS arm64 with official Docker images:

| Node.js / npm | Prisma / adapter / pg | PostgreSQL | Checks |
| --- | --- | --- | --- |
| 22.18.0 / 10.9.3 | 7.10.0 / 7.10.0 / 8.23.0 | 16.15, 17.11, 18.6 | 13/13 on each server |
| 24.7.0 / 11.5.1 | 7.10.0 / 7.10.0 / 8.23.0 | 16.15, 17.11, 18.6 | 13/13 on each server |

Every run generated byte-identical client files and recorded the same source
identity; each recorded, replayed and searched against its own server. The gate
at commit `000224d`, which only enlarged its search budgets and packs the same
archive bytes, passed again on Node.js 24.7.0 with PostgreSQL 17.11 and on
Node.js 22.18.0 with PostgreSQL 16.15. See the
[qualification record](../../docs/qualification/prisma-orm-7.10.0-2026-09-27.md)
for durations, search sizes and the additional negative checks.

A passing single sample is recorded with `run --max-runs 1`; the search then
stops at its one-run budget and the CLI exits 4. The gate requires
`stopReason: "max-runs"` together with a retained run whose outcome is `passed`.
An exhausted frontier describes the schedules that Interleave's search modeled,
not every possible execution.

Run the gate from the repository root with Node.js 22.18.0 or 24.7.0 selected.
It needs registry access (or a warm npm cache) and Prisma's binary host for the
schema engine:

```sh
npm ci --ignore-scripts
npm run build
mkdir -p ../interleave-runtime
npm pack --ignore-scripts --pack-destination ../interleave-runtime
TEST_DATABASE_URL='<dedicated PostgreSQL administrator URL>' \
INTERLEAVE_PRISMA_RUNTIME_ARCHIVE=../interleave-runtime/pavangupta352-interleave-<version>.tgz \
INTERLEAVE_PRISMA_EVIDENCE=../prisma-evidence \
npm run test:prisma
```

`INTERLEAVE_PRISMA_EVIDENCE` must name a directory that does not exist yet and
has no `node_modules` in any ancestor. `INTERLEAVE_PRISMA_RUNTIME_SHA256`
optionally requires an exact archive hash. The evidence keeps the setup commands
(`setup/`), the generated-client inventory, numbered command records, every run
artifact, the journals, `identity.json`, the search summaries, `cleanup.json`
and `results.json`. Prisma's engine cache is kept in `prisma-cache/`.

## Limits

- **Portable export is not supported for Prisma 7.10.0.** The original
  `@prisma/client-7.10.0.tgz` is 26,828,688 bytes. Shared export accepts at most
  16 MiB per archive, whether downloaded from the registry (`Archive download
  exceeds 16 MiB`) or supplied with `--dependency-archive` (`File exceeds the
  16777216 byte limit`). The same per-file bound applies when an export is
  verified and installed. No bundle is created; record and replay against the
  original application instead.
- Exact replay covers one Node.js and PostgreSQL version pair. Artifacts were not
  replayed across versions.
- Retries handle only `P2034`/40001 and the example's own stale-stock signal.
  Deadlocks (40P01), relation queries, nested writes, `createMany`, raw queries
  beyond the observation query, Accelerate, Prisma Postgres, other drivers or
  adapters, shared pools across actors, migrations applied by `prisma migrate`,
  and Prisma 8 are not qualified.
- Interleave does not observe whether a cycle carried a Parse message; statement
  reuse is shown by the session's `pg_prepared_statements` and by PostgreSQL
  accepting the retried commands.
- Inside an interactive transaction, send every query through the transaction
  client `tx`: with `max: 1`, the open transaction holds the actor's only
  connection. Interleave's actor profile allows one command-producing connection
  per actor, so a larger pool is not a substitute.
- Observed on macOS arm64 only.
